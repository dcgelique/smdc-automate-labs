AM: Service Operations

Lab 1 - Read, filter, and count ticket data

Outcome: Rebuild the Service Operations Insights flow completed during the workshop.

  1. Download the supplied ticket workbook, upload it to OneDrive or SharePoint, and confirm that the data is formatted as an Excel table named Tickets.
  2. In Power Automate, select Create → Instant cloud flow. Name the flow AM - Service Operations Insights - YourInitials and select Manually trigger a flow.
  3. Add Excel Online (Business) → List rows present in a table. Select the file location, document library, workbook, and Tickets table.
  4. Select Save, then Test → Manually. Run the flow and open the run history. Confirm that all eight supplied rows appear in the Excel action output.
  5. Add Filter array actions for the measures used during the session. Use the Excel value output in the From field.
  6. For each Filter array, add a Compose action using length(body('Filter_action_name')). Rename actions clearly, such as Count - Critical.
  7. Save and test again. Expand every Filter array and Compose action and compare the returned records and counts with Excel.
Troubleshooting order: file location → connection → table name → value array → action name → expression/dynamic content.

Lab 2 - Operational insights and email

Outcome: Turn validated ticket counts into a factual summary and send the workshop notification.

  1. Add a Compose named Operational Insights.
  2. Insert the validated counts from Lab 1. Keep the wording factual. Do not describe a category or priority as a confirmed root cause.
  3. Add a Condition after Operational Insights: Critical Count is greater than 0 OR High Count is greater than 0.
  4. In If yes, add Send an email (V2). Use your own or the controlled workshop email address.
  5. Use the subject Service Operations Alert - Priority Tickets Require Attention.
  6. In the body, include Total Tickets, Critical, High, and Critical + High counts. State that the message uses synthetic workshop data.
  7. In If no, add a Compose named No Priority Alert.
  8. After the whole Condition, add another Send an email (V2) so the full operational summary is always sent.
  9. Save, test manually, and compare every displayed value with the workbook.
Suggested summary:
Total Tickets: [Total]
Critical: [Critical]
High: [High]
Medium: [Medium]
Low: [Low]
Priority Attention: [Critical + High]

[Priority Attention] of [Total] tickets are Critical or High priority. This is a rule-based summary of the synthetic workshop dataset.

PM: Policy Approval and Resubmission

Lab 3 - Initial policy approval

Outcome: Rebuild the SharePoint approval workflow completed during the workshop.

  1. Open the shared workshop SharePoint site and the Policy Reviews list.
  2. Create an Automated cloud flow named PM - Policy Review - YourInitials.
  3. Select SharePoint → When an item is created or modified and configure the workshop site and Policy Reviews list.
  4. Add a Condition so the approval path continues only when Status equals Submitted. This prevents every list modification from starting an approval.
  5. Add Start and wait for an approval and choose Approve/Reject - First to respond, matching the delivered core lab.
  6. Set the approval Title using Policy ID and Policy Title. Set Assigned to using Reviewer Email.
  7. In Details, insert Process Owner, Review Cycle, policy details, and the SharePoint item or document link.
  8. Add a Condition where the approval Outcome equals Approve. Enter the value with the same capitalization.
  9. In both branches, add Update item to store Status, Decision, Comments, and Decision Date.
  10. Add outcome-specific Send an email (V2) actions to notify the process owner.
  11. Create a dummy SharePoint item, respond through Outlook, Teams, or the Power Automate approvals center, and inspect run history.
Remember: Start and wait for an approval pauses the flow until the approval is answered. The actions below it execute only after a response is received.

Lab 4 - Simplified resubmission

Outcome: Preserve Policy ID, increment Review Cycle, and route a revised policy through another approval.

  1. Create a second Automated cloud flow named PM - Policy Resubmission Review - YourInitials.
  2. Use When an item is created or modified on the Policy Reviews list.
  3. Add one Condition: Status equals Resubmitted.
  4. In If yes, add a Compose named New Review Cycle. Use the current Review Cycle value plus one:
    add(int(...Review Cycle...),1)
  5. Add Update item. Keep the same Policy ID, write the New Review Cycle, set Status to In Review, retain the revised-document link, and set Approval Start Date to utcNow().
  6. Add Start and wait for an approval. Include the revised policy details, the new review cycle, and prior reviewer comments.
  7. For the extension demonstrated during the session, choose Custom Responses - Wait for one response with Approve, Revision Required, and Reject.
  8. Add a Switch using the approval Outcome and update the SharePoint record in each case.
  9. Test by changing a Revision Required record to Resubmitted.
Simplified history approach: Keep the Policy ID, Review Cycle, previous comments, and current outcome on the same workshop record. A separate review-history list is a future production enhancement.

Follow-up and reminders

Lab 5 - Simple approval aging reminder

Outcome: Calculate how long an approval has been open and send a reminder when it exceeds three days.

  1. Create a Scheduled cloud flow named PM - Review Follow-up - YourInitials.
  2. Add SharePoint → Get items for the Policy Reviews list.
  3. Add Apply to each using the value output from Get items.
  4. Inside the loop, add a Compose named Approver Duration Days. Compare Approval Start Date with utcNow() using the facilitator-provided elapsed-time expression.
  5. Add one Condition: Approver Duration Days is greater than 3. This is a synthetic workshop threshold.
  6. In If yes, add Send an email (V2). Include Policy Title, current Status, Approval Start Date, and Approver Duration Days.
  7. In If no, take no action or add a Compose for testing.
  8. Test with records open for one, four, and eight days. Confirm only the four- and eight-day records send reminders.
Production note: Add a filtered Get items query so the flow retrieves only relevant pending approvals. Duplicate-reminder prevention, escalation tiers, and error-handling scopes are optional advanced improvements.
